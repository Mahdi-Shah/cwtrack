# راهنمای CLI چندسامانه‌ای

این راهنما قراردادهای اجرایی اتصال، دریافت، منابع، رابطهٔ تکلیف‌ها و Work را مشخص می‌کند. فرمان‌های قدیمی CW برای سازگاری باقی‌اند؛ مسیر یکپارچه از فرمان‌های حوزه‌ای استفاده می‌کند.

## فرمان‌ها و مسئولیت

| مسیر | کار اصلی | عامل |
|---|---|---|
| `cwtrack account list/connect/update/rename/forget` | دیدن اتصال‌های نام‌دار، ورود و چرخش امن رمز، تغییر نام و حذف اتصال | دانشجو و CLI؛ `access` نگهداری امن را انجام می‌دهد |
| `cwtrack study refresh` | دریافت فهرست از اتصال‌های انتخاب‌شده | دانشجو درخواست می‌دهد؛ Adapter داده می‌خواند؛ `study/catalog` نتیجه و تازگی را ثبت می‌کنند |
| `cwtrack study view/report` | مرور محلی کلاس‌ها، نگاشت‌ها، تکلیف‌ها و وضعیت مشترک | کد projection می‌سازد؛ دانشجو تصمیم می‌گیرد |
| `cwtrack study` یا `cwtrack study manage` | منوی تعاملی پیوند کلاس به درس و تغییر جاری/بایگانی/نامشخص | دانشجو انتخاب می‌کند؛ `catalog` تغییر نسخه‌دار را ذخیره می‌کند |
| `cwtrack study continue` | ادامهٔ OTP یا challenge تصویری معتبر | دانشجو ورودی می‌دهد؛ `access` همان continuation را ادامه می‌دهد؛ reCAPTCHA مرورگر در این مسیر متوقف می‌شود |
| `cwtrack resource view/attach/capture/update/detach` | مدیریت منبع و نسخهٔ محتوای ثبت‌شده | دانشجو مسیر را می‌دهد؛ `resources` اعتبار/نسخه را نگه می‌دارد؛ Codex محتوای قالب‌های خارج از استخراج خودکار را می‌خواند |
| `cwtrack relation list/add` | ثبت رابطهٔ اعلام‌شده بین تکلیف‌ها بدون ادغام Work | دانشجو دلیل و ارجاع‌ها را تأیید می‌کند؛ `catalog` ذخیره می‌کند |
| `cwtrack work list/get/start/group-start/group-get/save/sync/finish` | چرخهٔ پایدار کار تکی و گروهی، فایل‌ها و شواهد | Codex پاسخ را می‌سازد و بررسی می‌کند؛ CLI فایل/نسخه را ثبت می‌کند؛ دانشجو تحویل نهایی را انجام می‌دهد |

شناسهٔ داخلی اتصال و نام کاربری برای انتخاب به کاربر نمایش داده نمی‌شود. هر اتصال نام محلی دارد؛ اتصال‌های قدیمی نامی مانند «CW · اتصال 1» می‌گیرند. اگر انتخاب با نام مبهم باشد، عملیات نباید حدس بزند.

## ورودی فایل‌محور

برای عملیات پیچیده، فایل UTF-8 با ریشهٔ JSON از `--input-file` بدهید. اگر مسیر را ندهید و ترمینال تعاملی باشد، CLI مسیر فایل را راهنمایی‌شده می‌پرسد. رمز فقط در prompt مخفی گرفته می‌شود. متن پاسخ، رمز و شواهد خام را در argv ننویسید.

شروع کار دستی:

```json
{
  "manual": {
    "title": "نمونهٔ آموزشی",
    "course": "نمونهٔ درس",
    "prompt": "متن ساختگی برای نمایش قرارداد ورودی"
  }
}
```

ذخیرهٔ پیشرفت:

```json
{
  "expected_revision": 1,
  "progress": {
    "stage": "in_progress",
    "sections": [],
    "open_questions": [],
    "requirements": [],
    "checks": [],
    "limitations": []
  }
}
```

ثبت خروجی:

```json
{
  "expected_revision": 2,
  "delivery": {
    "files": [{"path": "./answer.txt", "role": "answer"}],
    "note": "فایل نمونه برای قرارداد CLI",
    "limitations": []
  }
}
```

فایل‌های واقعی کاربر را به مخزن مستندات اضافه نکنید. `finish` فقط رکورد Work را کامل می‌کند؛ سامانهٔ تکلیف را ارسال نمی‌کند. CLI آمادگی را از روی الزام‌ها، فایل‌های واقعی و شواهد جاری محاسبه می‌کند.

## منابع

`resource attach` و `resource capture` فقط وقتی موفق‌اند که منبع و محدوده معتبر باشند. استخراج خودکار متن برای TXT/MD/CSV است. PDF، Word، اسلاید و تصویر با ابزار مناسب Codex خوانده می‌شوند و فایل اصلی حفظ می‌شود. نوع ناشناخته باید `needs_extraction` باشد؛ منبع ناخوانا یا ناموفق، منبع استفاده‌شده محسوب نمی‌شود.

نمونهٔ فایل ثبت منبع:

```json
{
  "spec_or_id": {
    "title": "جزوهٔ نمونه",
    "location": {"kind": "file", "path": "./handout.pdf"}
  },
  "to": {"offering_id": "شناسهٔ درسِ نیم‌سال"},
  "extent": {"kind": "document"}
}
```

برای عنوان‌های مشابه در دو سامانه، Codex جزئیات هر `TaskRef` را با `collect_assignment` می‌گیرد و عنوان، متن سؤال، خروجی‌های لازم و پیوست‌های قابل‌خواندن را مقایسه می‌کند. تفاوت یا دادهٔ ناقص را نشان می‌دهد و از دانشجو می‌پرسد که تکلیف‌ها واقعاً یکی هستند یا نه؛ تا تأیید، رابطه یا Work تازه‌ای ساخته نمی‌شود.

فرمان `relation add` دلیل، فهرست `task_refs` و `relation_type` اختیاری می‌گیرد. مقدار پیش‌فرض `related` است؛ پس از تأیید صریح دانشجو برای یکسان‌بودن، `same_assignment` ثبت می‌شود و داشبورد انتشارها را در یک گروه نشان می‌دهد، در حالی که مهلت، وضعیت تحویل و Work هر سامانه جدا می‌مانند. برای تغییرات revisionدار، مقدار `expected_revision` را از view همان حوزه بخوانید. `resource detach` و `account forget` پیش از تغییر تأیید تعاملی می‌خواهند.

## گزارش و سازگاری

`cwtrack study report` نمای مشترک CW/کوئرا را می‌سازد: تعداد تکلیف هر سامانه، تازگی دریافت، درس پیوندخورده، وضعیت تحویل و مهلت شمسی کنار هر تکلیف می‌آید. وضعیتِ ارائه‌نشده از طرف سامانه «نامشخص» باقی می‌ماند. برای دیدن گزینه‌های هر بخش، از `cwtrack study --help`، `cwtrack account --help`، `cwtrack resource --help`، `cwtrack relation --help` و `cwtrack work --help` استفاده کن. `report`، `open` و `gaps` قدیمی CW-only می‌مانند تا scriptهای موجود رفتار دیگری پیدا نکنند. `fetch`, `store`, `raw`, `material` و `brief` نیز رفتار قدیمی خود را حفظ می‌کنند.

هر refresh ناموفق یا ناقص باید وضعیت و زمان تلاش را نشان دهد و آخرین دادهٔ کامل را پاک نکند. reCAPTCHA با `challenge_unavailable` متوقف می‌شود؛ صفحهٔ کوئرا برای اقدام دستی معرفی می‌شود اما حل مرورگر به‌عنوان ورود API ثبت نمی‌شود. شروع درخواست تازه تنها با اجرای صریح دوبارهٔ فرمان توسط دانشجوست.
