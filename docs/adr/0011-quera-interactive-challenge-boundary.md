# مرز challenge تعاملی کوئرا و نشست API

reCAPTCHA کوئرا در مرورگر حل می‌شود، اما token آن به نشست HTTP محلی Adapter منتقل نمی‌شود. بنابراین CLI یا API نباید بعد از نمایش راهنمای سایت، ورود یا دریافت را موفق اعلام کنند.

اگر Adapter به reCAPTCHA برسد، مسیر API با وضعیت `challenge_unavailable` متوقف می‌شود و کاربر به صفحهٔ ورود کوئرا راهنمایی می‌شود. حل challenge در سایت دستی است. فقط درخواست صریح تازهٔ دانشجو یک تلاش تازه از ابتدا آغاز می‌کند؛ اگر همان درخواست دوباره به challenge برسد، توقف تکرار می‌شود. OTP معمولی همچنان فقط به continuation ذخیره‌شده و معتبر پاسخ داده می‌شود.

این تصمیم از جعل ورود موفق و ارسال token خارج از مرز امن جلوگیری می‌کند. هزینه‌اش باقی‌ماندن بعضی دریافت‌های زنده به‌عنوان مرحلهٔ دستی است؛ پذیرش زنده باید این محدودیت را ثبت کند و هیچ token یا دادهٔ challenge را در شاهد پالوده نگه ندارد.
