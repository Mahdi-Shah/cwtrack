# cwtrack

تکالیف، مهلت‌ها و منابع درسی‌تان را روی **cw.sharif.ir** — سامانهٔ آموزشی دانشگاه
شریف — پیگیری کنید و یک نگاه ببینید چه چیزی هنوز تحویل نداده‌اید.

دو مهارت OpenCode و یک بستهٔ کوچک پایتون. بدون هیچ وابستگی اجباری، بدون سرور، بدون
ردیابی.

```powershell
cwtrack fetch     # ورود، دانلود، ذخیره
cwtrack ui        # باز کردن داشبورد
cwtrack brief     # ساختن پوشهٔ کار برای کاری که سررسید شده
```

## چه می‌کند

| دستور | |
|---|---|
| `fetch` | وارد می‌شود، صفحهٔ تکالیف همهٔ درس‌ها را دانلود می‌کند، ذخیره می‌کند |
| `ui` | یک داشبورد HTML مستقل می‌سازد و باز می‌کند |
| `gaps` | چه چیزی باقی مانده، بدترین اول — نسخهٔ کوتاه |
| `open` | فقط فهرست کارهای انجام‌نشده |
| `report -o out.md` | گزارش کامل فارسی به‌صورت markdown |
| `brief` | پوشهٔ کار با بریفِ پیش‌پرشده برای یک تکلیف |
| `material --course N` | پوشهٔ منابع آن درس را نشان می‌دهد |
| `store` / `raw` | پارس دوبارهٔ dump موجود / فهرست HTMLهای ذخیره‌شده |

همهٔ دستورها جز `fetch` فقط فایل محلی می‌خوانند. بدون شبکه، بدون کپچا.

**`-o` روی همهٔ دستورهای متنی کار می‌کند** — که مهم است چون خروجی فارسی در کنسول
پیش‌فرض ویندوز (cp1252) خراب می‌شود:

```powershell
cwtrack gaps -o gaps.txt
Get-Content gaps.txt -Encoding UTF8
```

## چرا داشبورد و نه فقط یک جدول

جدولی از تاریخ‌ها به شما نمی‌گوید که سه چیز هم‌زمان فردا سررسید است. داشبورد با
**«الان چه کاری مانده»** شروع می‌کند — یعنی واقعاً چه چیزی باقی است — بعد خط زمانی
۳۰ روز، بعد شمارش‌ها، و بعد یک کارت جمع‌شونده برای هر درس.

مهلت‌هایی که در یک روز می‌افتند یک تیک مشترک دارند و برچسب‌هایشان روی هم چیده
می‌شود، تا یک روز شلوغ یک نشانه با چند اسم باشد، نه چند نشانه که برای یک پیکسل
با هم می‌جنگند.

یک فایل HTML است با فونت‌هایی که به‌صورت data URI داخلش جاسازی شده‌اند. بدون
سرور، بدون مرحلهٔ build، بدون چیزی برای نصب. شمارش معکوس هر ۳۰ ثانیه تازه می‌شود،
پس تبی که شب باز مانده بی‌صدا غلط نمی‌شود.

## `brief` — اتصال به مهارت دیگر

`cwtrack` می‌داند تکلیفی وجود دارد و کِی سررسید است. `university-assignment` می‌داند
سند چطور ساخته می‌شود. `brief` همان فایلی را می‌نویسد که این دو را وصل می‌کند:

```
work/<course>/<assignment>/
├── brief.md      آنچه سایت می‌داند، و آنچه نمی‌دهد
├── HANDOFF.md    قدم بعدی، به ترتیب
├── draft.md      جای پاسخ
└── source/       منابع درس
```

`brief.md` دربارهٔ تنها چیزی که سایت به ما نمی‌دهد — **متن تکلیف** — صریح است، تا
کسی با اطمینان به سؤال غلط جواب ندهد. بدون `--force` پوشهٔ موجود را بازنویسی
نمی‌کند، چون بخش‌های ۲ تا ۷ مال خودتان است.

## کپچا

cw.sharif.ir روی فرم ورود یک کپچای تصویری می‌گذارد. `fetch` تصویر را ذخیره
می‌کند و از شما می‌خواهد بخوانیدش.

**خودکار حل نمی‌شود و نخواهد شد.** کپچا اعلام صریح سایت است که یک انسان پشت کیبورد
است؛ حل‌کنندهٔ خودکار ابزار دور زدن ربات است نه کمک درسی، و بسته‌بندی‌اش کنار
فایل‌های تکالیف شما معاملهٔ بدی است. غیرقابل‌اتکا هم هست — کپچاهای با کاراکتر
تحریف‌شده اغلب OCR را شکست می‌دهند و مدام باید دوباره اجرا شود.

یک نکتهٔ عملی: تصویر حدود ۱۹۰×۴۰ پیکسل است و در آن اندازه واقعاً سخت خوانده
می‌شود. اگر رد شد، دوباره اجرا کنید.

## دامنه، صادقانه

**فقط روی cw.sharif.ir تست شده.** نه Moodleهای دیگر، نه دانشگاه‌های دیگر.

تم (`mb2nl`)، مهلت‌های شمسی، پلاگین کپچا و جدول چهارستونی تکالیف همه مختص همین
نصب‌اند. ساختار *Moodle* عمومی است، ولی راهی برای تست یک آداپتور عمومی ندارم و
انتشار چیزی که نتوانستم اجرا کنم ادعا است نه فیچر. پس ابزار همان را می‌گوید که
هست.

محدودیت‌های شناخته‌شده — همه تست‌شده و مستند، نه دورزدهی بی‌صدا:

- **نام فایل انگلیسی تقریبی تطبیق داده می‌شود.** `HW4_Oscillator.pdf` با
  `Homework 4 — Oscillator` تطبیق نمی‌کند؛ یک توکن مشترک دارند و تطبیق‌دهنده دو
  توکن می‌خواهد. نام فارسی درست تا می‌شود (ک/ك، ی/ي، ارقام فارسی و عربی، نیم‌فاصله).
- **نبودِ فروشگاه داده با صدای بلند شکست می‌خورد.** هرگز صفر گزارش نمی‌کند، چون
  «تکلیفی نداری» و «داده‌ات را پیدا نکردم» دو ادعای متضادند.
- **وضعیت ناشناخته هرگز `submitted` نمی‌شود.** در `unknown` می‌افتد و در گزارش
  صریح گفته می‌شود. خطای پارسر نباید تکلیفِ تمام‌شده به نظر برسد.
- **«چیزی پیدا نشد» یعنی «چیزی وجود ندارد» نیست.** درسی که تکلیفی نشان نمی‌دهد
  یعنی در لحظهٔ آخرین بررسی نداشته. وسط ترم تکلیف اضافه می‌شود.

## تقویم شمسی

مهلت‌ها در این سایت فارسی‌اند و معمولاً سال ندارند: `Tomorrow, 14 مهر, 7:30 صبح`.

تبدیل وقتی `jdatetime` نصب باشد از آن استفاده می‌کند، وگرنه جدول نوروز داخلی
شمسی ۱۳۸۰–۱۴۴۲ (۲۰۰۱–۲۰۶۱) را پوشش می‌دهد که هر ترم جاری و آیندهٔ نزدیک را
در بر می‌گیرد. بیرون از آن بازه، به‌جای حدس زدن چیزی برنمی‌گرداند.

آن جدول با چهار invariant اعتبارسنجی شده، چون فرمول کوتاه «۳۳ ساله»‌ای که در
اینترنت می‌چرخد به‌اندازه‌ای غلط است که اهمیت داشته باشد — دو تلاش در این پروژه
نوروز را ۲۲ مارس گذاشت و سال‌های ۳۶۴ و ۳۶۷ روزه ساخت:

- نوروز در کل بازه همیشه ۲۰ یا ۲۱ مارس است
- طول سال همیشه ۳۶۵ یا ۳۶۶ روز است
- دقیقاً ۸ سال کبیسه در هر چرخهٔ ۳۳ ساله
- هر روزِ یک سال به روزهای متوالی میلادی نگاشت می‌شود، و هر دو مسیر روی تمام
  روزهای یک بازهٔ سه‌ساله توافق دارند

## ایمنی

**فقط خواندنی.** هیچ بارگذاری، هیچ ارسال، هیچ نوشتنی روی سایت وجود ندارد. تحویل
کار، کلیک خودتان است در مرورگر خودتان، بعد از اینکه آن را خوانده‌اید.

**فقط حساب خودتان.** هیچ‌چیز دانشجوی دیگر را فهرست نمی‌کند، و نباید هم بشود.

**داده‌اتان روی همان دستگاه می‌ماند.** `cw-data/`، `.cw/`، `work/` و `reports/` در
`.gitignore` هستند، و همین‌طور `.env`، فایل توکن و فایل نشست. dump خام صفحه‌ها
شامل `sesskey` زنده در لینک logout است — هرگز یکی را commit نکنید.

**اطلاعات ورود هرگز وارد فایل نمی‌شود.** از `CW_USER` / `CW_PASS` در متغیر محیطی،
یا از یک prompt بدون echo. نه از argv، چون argv در تاریخچهٔ شل و در فهرست
پروسه‌ها دیده می‌شود.

## توسعه

```powershell
pip install -e ".[dev]"
pytest              # ۲۷۸ تست، بدون شبکه، بدون حساب، بدون شبکه، بدون حساب
ruff check src tests
```

قبل از اینکه به یک اجرای سبز اعتماد کنید، از یک clone تمیز نصب کنید. بیشتر
باگ‌هایی که حین ساخت این پیدا شدند در پوشهٔ کاری خودشان دیده نمی‌شدند و فقط
وقتی بسته جای دیگری نصب شد ظاهر شدند — یک وابستگی devِ جاافتاده، فایلی که
wheel جا انداخته بود، یک guard در زمان import که فقط روی کنسول واقعی فعال
می‌شود.

تست‌ها کاملاً روی fixtureهای پاک‌شده در `tests/fixtures/` اجرا می‌شوند — شکل واقعی
صفحه با هر شناسه جایگزین‌شده. هیچ تستی یک capture واقعی نمی‌خواند.

دو جایی که باگ‌ها واقعاً زندگی می‌کردند، دو ماژولی هستند که بهتر تست شده‌اند:

- `dates.py` — به‌جای مثال، property روی یک بازه. یک لنگرِ سال ۱۴۰۴ هر دو نسخهٔ
  خراب تبدیل تاریخ را رد می‌کرد.
- `classify.py` — تقدم به‌عنوان یک کل تست شده، چون دو واقعیت زیررشته‌ای آن را
  می‌رانند: `"not submitted"` رشتهٔ `"submitted"` را در بر دارد، و یک ردیف
  `"Draft"` حتی با عددی در ستون نمره تحویل‌شده نیست. نسخهٔ قبلی برعکس عمل کرد و
  چهار تکلیفِ انجام‌نشده را تحویل‌شده گزارش کرد.
